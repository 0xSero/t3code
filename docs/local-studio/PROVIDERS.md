# Upstream providers against Local Studio models

Owner decision 6: every upstream T3 provider driver whose CLI can target a custom endpoint also runs against the Local Studio gateway. This works through upstream's own per-instance configuration. The drivers are unchanged, and no hook was added.

## How it works

- `apps/server/src/provider/localStudio/LocalStudioProviderSync.ts` is a scoped layer merged into `localStudioRouteLayer`, so it adds no upstream edit. It runs at startup and then every 20 seconds.
- Each pass:
  1. It checks `GET <gateway>/health` (`service === "local-studio"`) and reads `GET <gateway>/v1/models`, keeping models whose `local_studio.state === "ready"`.
  2. It picks the drivers whose CLI is installed. That means the legacy `providers.<driver>.binaryPath` when the user set one, otherwise the default binary name on `PATH`.
  3. It gets a per-client gateway key. The key already stored for the instance is checked with `GET /v1/models` and a Bearer token. On any non-2xx response, the server asks for a new key with `POST /api/keys {client, label: "t3", scope: "client"}` over loopback, sending no `Origin` header.
  4. It writes the driver's isolated home under `~/.local-studio/agents/t3/<driver>`. `LOCAL_STUDIO_AGENT_HOME` overrides that location.
  5. It upserts `providerInstances["localstudio-<driver>"]` for the upstream driver kind. The entry is named `<Driver> · Local Studio` and holds the gateway models in `config.customModels`. The environment carries the gateway URL and the key.
- The key is stored as a `sensitive` instance environment variable. Upstream's settings service moves it into the T3 secret store, and on disk it appears as `valueRedacted: true`. The key is never written to `settings.json`, and never to the isolated home.
- The first time an instance is created, the sync runs the CLI's `--version` (and `models` for Grok and OpenCode) with the instance environment. This warms the fresh home. Without it, the first status probe timed out (OpenCode after 4 s, Grok's ACP initialize after 8 s) and the instance showed as Unavailable or Limited until T3 restarted.
- Changes you make are kept:
  - If you edit the display name, accent colour or `enabled` flag of a `localstudio-*` instance, the next sync keeps your values.
  - If you delete an instance, it is recorded in `~/.local-studio/agents/t3/t3-instances.json` and is not created again.
- When models are launched or stopped, the change is written to `customModels`. Upstream then rebuilds that instance, and sessions running on it restart.
- No output cap is set:
  - No generated config sets `max_tokens`, `max_output_tokens` or a thinking budget.
  - OpenCode needs a `limit.output` value, so it is set to the model's context window.
  - The gateway also strips `max_tokens`, `max_completion_tokens` and `max_output_tokens` on every dialect (`apps/controller/src/gateway/upstream.ts`).
  - The gateway's request log showed `capsStripped: []` for all the verified requests.

## Known limits

- **Extra models in some pickers.** Codex's `model/list` and Claude's bundled catalog still list their built-in models (for example `GPT-6-*`, Claude models) under the Local Studio instance, next to the gateway models. Picking one of those sends a model id the gateway does not serve, and the request gets a 404. OpenCode lists only gateway models. Grok lists the gateway models plus T3's own `Grok Build` entry, which runs the session's default model; that is set to the first ready gateway model.
- **No per-thread workspace attribution.** Requests are attributed to the client through the per-client key and the `X-Local-Studio-Client` header. The static per-instance config has no thread id, so `X-Local-Studio-Workspace` is not sent.
- **Grok is only partly isolated.** Even with its own `GROK_HOME`, Grok still loads MCP servers from `~/.claude.json` and `~/.cursor/mcp.json`.
- **Instance rebuild on model change.** Launching or stopping a model changes `customModels` (and OpenCode's config content), which rebuilds that instance.

## Reproduce

```sh
LOCAL_STUDIO_AGENT_HOME=<scratch>/agents node apps/server/dist/bin.mjs serve --host 127.0.0.1 --port <p> --base-dir <scratch>/t3home <scratch>/proj
```

- Within one sync pass, the log shows `Local Studio issued a gateway key` for each installed driver, then `Local Studio provider instances synced` with the list of ready models.
- In the model picker, `Codex · Local Studio`, `Claude · Local Studio`, `Grok · Local Studio` and `OpenCode · Local Studio` are listed, each with `glm-5.3-flash`.
